## 15:00 · Circuits: Impedances

**Lecturer:** Prof Neil White. **This week:** Impedances, beginning with NMW04. The topics below span the weekly material; today's stopping point is not specified.

- A sinusoidal voltage or current can be represented by a complex phasor carrying magnitude and phase. This replaces differential equations in sinusoidal steady state with algebra, while retaining the phase relationship between signals.
- Component impedance depends on angular frequency: a resistor has impedance $R$, an inductor $j\omega L$, and a capacitor $1/(j\omega C)$. Increasing frequency increases inductive reactance but decreases capacitive reactance.
- Series impedances add; parallel branches are combined through reciprocal impedances. Voltage and current dividers still work, but their ratios are complex, so the result has both a magnitude and a phase angle.
- Admittance $Y=1/Z$ is useful for parallel circuits. Resistance and reactance describe impedance; conductance and susceptance describe admittance.
- An RL high-pass circuit takes its output across the inductor: $H(j\omega)=j\omega L/(R+j\omega L)$. The output tends to zero at DC and unity at high frequency, with corner angular frequency $\omega_c=R/L$.

**Main takeaway:** familiar circuit laws still apply to AC, provided phase is tracked alongside magnitude.

**Useful preparation:** practise rectangular-to-polar complex conversion, complex division and the relation $\omega=2\pi f$. Check why the inductor-output circuit passes high rather than low frequencies.

## 16:00 · Programming: Data Structures & Dynamic Memory Allocation

> [!note] Topic for today is tentative
> The topics below cover the published L6 material. Its placement in today's lecture and the lecturer are not yet confirmed by a dated schedule.

- Structures group related values into one record. Access a member with `object.member`, or use `pointer->member` when working through a pointer. `typedef` gives a type a convenient name.
- A structure's size need not equal the sum of its member sizes: alignment can introduce padding. Use `sizeof` rather than assuming a byte count when allocating storage.
- `malloc` obtains dynamic storage and `free` releases it. Allocation size, lifetime and ownership must be explicit: returning a pointer to allocated storage can be valid, whereas returning a pointer to an expired local variable is not.
- Dynamic one- and two-dimensional arrays require both allocation and a matching cleanup strategy. Distinguish the data's layout from the pointers used to reach it.
- Headers describe interfaces; implementation files contain definitions. Separate compilation and `make` dependencies allow larger programs to be rebuilt without recompiling everything unnecessarily.
- `argc` and `argv` expose command-line arguments. Arguments arrive as strings, so numerical inputs require conversion rather than being used directly as numbers.

**Main takeaway:** choose a suitable representation for related data, and be able to explain who owns dynamically allocated memory and when it is released.

**Useful preparation:** revise pointer dereferencing and address-taking. Trace a small structure through both dot and arrow access, then sketch the lifetime of a dynamically allocated array from allocation to release.

## 17:00 · Digital Systems: FPGAs and Programmable Logic

**Lecturer:** Prof Mark Zwolinski. **Confirmed topic:** FPGAs and Programmable Logic.

- A ROM can implement a truth table: the inputs select an address and the stored bits provide the outputs. This is general, but can waste capacity when much of the table or input space is unnecessary.
- PALs, CPLDs and FPGAs offer different programmable structures. Compare a programmable logic matrix, collections of macrocells, and the configurable logic blocks of an FPGA rather than imagining a bag of conventional discrete gates.
- FPGA lookup tables implement logic functions; registers store state; programmable interconnections connect blocks. A design's structure determines its use of these resources.
- The implementation flow converts a hardware description into logic, places that logic onto the device and routes the connections. Simulation checks behaviour, and timing matters as well as logical correctness.
- Hardware description is not ordinary sequential software. Operations can occur concurrently, and the description determines the circuitry built rather than a list of CPU instructions.

**Main takeaway:** describe a circuit that tools can implement, not a program for a processor to execute.

**Useful preparation/research:** identify the roles of ModelSim and Quartus. Find a Cyclone V logic-element count and a comparable Xilinx FPGA. Select and state a specific Cyclone V device, since capacity varies across the family.

Sources: [Introduction and Programmable Logic slides](https://moodle.ecs.soton.ac.uk/pluginfile.php/85730/mod_resource/content/5/mz%20L1%20Intro.pdf) · [Digital Systems module](https://moodle.ecs.soton.ac.uk/course/view.php?id=901).
