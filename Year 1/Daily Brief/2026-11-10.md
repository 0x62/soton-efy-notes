## 09:00–10:00 · Digital Systems: sequential design and testbenches

**Lecturer: Professor Mark Zwolinski.** The dated schedule lists **Sequential SystemVerilog 3**. At **42:42–42:50 in yesterday's recording**, he explicitly previews more sequential-logic design and writing testbenches for today's 09:00 lecture. The current deck covers general sequential systems and testbenches; the exact stopping point remains to be established in class.

### What to understand

- **Separate the controller from the datapath.** The datapath stores and processes values. The controller decides which operation happens and when, using status signals returned by the datapath. This avoids describing every bit of a large system as one enormous state machine.
- **Registers give transfers a time boundary.** In register-transfer notation, $R\leftarrow S$ means loading the value into R at the relevant clock boundary. R then retains that value until another load. A changing source is not the same thing as continuously changing the stored destination.
- **Design the interface between blocks.** An enable tells a counter when to advance; a ready or completion output tells a controller when it may proceed. Check the meaning and timing of each signal, rather than assuming independently written blocks fit together.
- **A testbench surrounds the design under test.** It instantiates the DUT, generates clock/reset/input stimulus, and checks responses. Unlike a hardware interface module, the top-level testbench normally has no ports.
- **Simulation timing matters.** Initialise the clock, give reset a deliberate sequence, and drive any one signal from only one process. `$display` and `$strobe` observe at different points in the simulation time step; `$strobe` can report the value after scheduled updates have settled.

### Small example: clock and reset timing

For an illustrative testbench, start a clock at 0 and toggle it every **5 ns**. A full cycle is **10 ns**, so the frequency is **100 MHz**, not 200 MHz. For an active-low reset, a high-to-low transition asserts reset and returning high releases it. Check that the DUT reaches its reset state, then examine what changes at each active clock edge.

Yesterday's lecture linked an ASM chart to a two-process SystemVerilog state machine: a clocked state register and combinational next-state/output logic. Default combinational assignments prevent unintended memory. Today's controller/datapath split builds on that distinction.

**Useful prep:** revisit the traffic-light controller and binary counter. Sketch which block starts the timer, which block reports completion, and which signals must be sampled on a clock edge. The deck asks how to adapt the counter with enable/ready signals and whether it then fits the controller.

**Takeaway:** a working sequential system needs both correct logic and a clear agreement about when information moves between blocks.

## 14:00–17:00 · T14: Bus Operation and Control

**Location: Building 59, level 2, ECS Teaching Lab, 59/2213.** This session uses the PlayBus design, simulation tools and the DE1-SoC FPGA board to investigate moving data between components.

### What the lab is developing

- **A shared bus carries data between sources and destinations.** Sources include memory and switches; destinations include RAM and an LED register. Control signals determine which transfer is taking place.
- **Selection must be unambiguous.** Understand which source is selected and which destination is allowed to capture data. Multiple enabled sources are an error, not a way to combine values.
- **A register preserves a result.** A source can change after a transfer while the destination register continues to hold the captured value. This connects directly to today's sequential-design lecture.
- **Simulation should explain hardware behaviour.** Record the control settings, predicted result and observed waveform before moving to the board. Investigate undefined or conflicting values rather than treating them as meaningful data.

## 17:00–18:00 · Mathematics: first-order ordinary differential equations

**Lecturer: Bing Chu.** The Week 8 preparation is **first-order ODEs**; Week 9 moves to second-order ODEs. Today's exact subsection is not specified in the published week-wide plan, so use the following as preparation rather than a claim that every method will be taught tonight.

### What to understand

- **An ODE connects a function to its derivatives.** Its order is the highest derivative appearing. A first-order equation typically has a family of solutions containing one arbitrary constant.
- **An initial condition selects one member of that family.** For $y'=\cos x$, integration gives $y=\sin x+C$. Requiring $y(0)=1$ gives $C=1$.
- **Check a solution in two ways:** substitute it into the differential equation, then separately check the initial condition.
- **A direction field gives local slopes.** Euler's method turns this into a step-by-step approximation, $y_{n+1}=y_n+h f(x_n,y_n)$. A smaller step generally improves the approximation, but it is still not an exact solution.
- **Recognise the equation before choosing a method.** The first-order deck progresses through separable equations, substitutions, exact equations and integrating factors. Do not force separation onto an equation that is not separable.

### Engineering example: a discharging capacitor

The slides use a source-free RC circuit with

$$V+RC\frac{dV}{dt}=0.$$

Rearrange to $dV/dt=-V/(RC)$. The solution satisfying $V(0)=V_0$ is

$$V(t)=V_0e^{-t/(RC)}.$$

**Illustrative values:** with $R=10\,\mathrm{k\Omega}$ and $C=100\,\mathrm{\mu F}$, the time constant is $RC=1$ second. Starting at 5 V gives $V(1)=5/e\approx1.84$ V. The initial condition sets the starting voltage; the circuit parameters set the decay rate. Differentiating the solution verifies the original equation.

**Useful prep:** the Week 8 page assigns the four first-order ODE videos, the theory/application slides and the tutorial sheet. Refresh integration and the chain rule, then try identifying equation types before solving. The deck references Kreyszig, 10th edition, Chapter 1, particularly §§1.1–1.5 and 1.7.
